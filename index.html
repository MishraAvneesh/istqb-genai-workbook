Chapter 1 · 100 min
LLM Explorer — Compare 3 LLMs Side by Side
Understand GenAI foundations by experiencing LLM differences hands-on
~45 min ▼
🎯 What you'll learn
LLM Explorer
You'll prompt 3 different LLMs with the exact same test-related prompt and compare their outputs. This directly maps to the syllabus concept of Foundation vs Instruction-tuned vs Reasoning LLMs — you'll feel the difference rather than just reading about it.
ChatGPT Claude Gemini
1
Pick a simple app to test — use a login page or signup form. It can be totally imaginary. Just write: "The app has a username field, password field, and a Login button."
2
Run this same prompt in all 3 LLMs and save each response in a doc or notes app. See the prompt template below.
3
Try the multimodal step: Go to Gemini or ChatGPT. Take a screenshot of any app's login page (your email, bank, any app). Upload the image and ask: "Generate 5 test cases from this UI screenshot."
4
Compare and note: Which LLM gave more specific test cases? Which one mentioned edge cases? Which felt more creative? Write 3 bullet observations.
📋 Prompt Template 
Role: You are a senior software QA engineer.

Context: We are testing a simple login page. It has:
- A username field (accepts email format)
- A password field (min 8 characters)
- A "Login" button
- A "Forgot Password" link

Instruction: Generate 8 test cases for this login page.

Constraints: Include at least 2 negative test cases 
and 1 boundary value test case.

Output Format: Return as a numbered list with:
Test ID | Test Case Name | Steps | Expected Result
✅ What you'll have learned

You'll see how Instruction-tuned LLMs (ChatGPT, Claude) follow structure better than general models. You'll understand tokenization/context by noticing when an LLM "loses" info from a long prompt. Multimodal exercise ties directly to syllabus section 1.1.4.

Chapter 2 · 365 min · MOST IMPORTANT
Prompt Lab — Build Your Personal Prompt Library
Master the 6-part structure + 5 techniques across real test tasks
~120 min ▼
🎯 What you'll learn
The Prompt Lab
You'll run 3 distinct prompt engineering exercises — each targeting a different technique. By the end you'll have a real personal prompt library: reusable templates for test analysis, test design, and test data generation.
ChatGPT Claude
A
Exercise A — Zero-shot vs Few-shot: Use the zero-shot prompt below to generate acceptance criteria. Then use the few-shot version. Compare quality. You'll see immediately why examples matter.
B
Exercise B — Prompt Chaining (3 steps): Step 1: Ask LLM to extract all testable conditions from a user story. Step 2: Feed that output back — ask it to generate test cases for each condition. Step 3: Ask it to flag which test cases should be automated first.
C
Exercise C — Meta Prompting: Ask the LLM: "Write me the best possible prompt to generate synthetic test data for an e-commerce checkout that covers edge cases without exposing real PII." Then use that AI-generated prompt!
D
Save your 3 best prompts in a prompt-library.md file. This becomes your personal study artifact and exam memory aid.
📋 Few-Shot Prompt Template (Exercise A) 
Role: You are a QA engineer writing acceptance criteria in 
Gherkin format.

Context: We're testing an e-commerce checkout module.

Examples (few-shot):
User Story: "User can apply discount code"
Acceptance Criteria:
  Given a valid discount code exists
  When the user enters the code at checkout
  Then the discount is applied to the total

User Story: "User can save payment method"
Acceptance Criteria:
  Given the user is logged in
  When they enter valid card details and check "Save"
  Then the payment method is stored securely

Instruction: Now write acceptance criteria for:
"As a user, I want to receive an order confirmation email 
after placing an order."

Constraints: Include at least one negative scenario.
Output Format: Gherkin (Given/When/Then)
✅ What you'll have learned

You'll have hands-on experience with all 5 prompting techniques. You'll understand exactly why the 6-part structure improves output quality. Your prompt library is a real deliverable you can reference on exam day.

Chapter 3 · 160 min
Risk Lab — Spot the Hallucination & Attack the LLM
Discover GenAI defects and security risks by deliberately triggering them
~60 min ▼
🎯 What you'll learn
The Risk Lab
You'll deliberately create conditions that trigger hallucinations, reasoning errors, and privacy risks — then apply mitigations and see the improvement. This is the most memorable way to learn Chapter 3 content.
ChatGPT Claude
1
Trigger a hallucination: Give the LLM a vague, fictional requirement with no context. Ask for test cases. Check if it invents features that don't exist. Note what it made up.
2
Mitigate it: Re-run with better context and constraints. Compare how many "invented" test cases disappear when you improve the prompt.
3
Test temperature: If using ChatGPT API playground (free), set temperature to 0.0 then 1.5 on the same prompt. See how consistency changes. With Claude/ChatGPT chat, try "Be very precise and deterministic" vs "Be creative" in the system prompt.
4
Privacy exercise: Ask LLM to generate test data for a user registration form. Notice if it creates realistic-looking names/emails/phone numbers (PII risk). Then ask it to generate synthetic data instead. Compare the two outputs.
5
Research standards: Go to Perplexity.ai and search "ISO 42001 AI management system summary". Read what it returns. Note: this is grounded, cited output — much less hallucination risk than a plain LLM answer.
📋 Hallucination Trigger Prompt 
Vague prompt (will likely hallucinate):
Generate test cases for the XYZ banking app.

---
Improved prompt (reduces hallucination):
Role: You are a QA engineer.
Context: We are testing a banking app with ONLY these features:
  1. View account balance
  2. Transfer money between own accounts
  3. View last 10 transactions
Instruction: Generate 6 test cases covering ONLY the features listed above.
Constraints: Do NOT add test cases for features not listed.
Output Format: Table with columns: ID | Feature | Test Case | Expected Result

After running both, check:
Did the vague prompt invent features like "loan application" 
or "credit card payment"? That's a hallucination!
✅ What you'll have learned

You'll have directly experienced all 3 GenAI defects. You'll understand that better prompts = fewer hallucinations. You'll know what synthetic test data looks like vs PII-containing data. All Chapter 3 exam scenarios will feel familiar.

Chapter 4 · 110 min
RAG in Action — Build a Test Q&A Bot from Your Own Docs
Experience RAG architecture firsthand using free no-code tools
~45 min ▼
🎯 What you'll learn
RAG in Action
Using Google's free NotebookLM tool, you'll upload a test requirements document and see RAG in action — the LLM answers questions grounded in YOUR document, not hallucinated from training. Then you'll compare with and without RAG.
NotebookLM ChatGPT
1
Create your test document: Write a simple 1-page requirements doc for a fictional app. Include 5 specific features with details. Save as a PDF or Google Doc. (You can use AI to generate this doc first!)
2
Without RAG (baseline): Go to ChatGPT. Paste just the app name (e.g., "MediTrack — a medical appointment app"). Ask: "What test cases should I write?" See what it generates — it'll make assumptions.
3
With RAG via NotebookLM: Go to notebooklm.google.com → Create notebook → Upload your requirements doc. Now ask the same question. See how it references specific sections from YOUR document.
4
The "agent" simulation: Back in ChatGPT, try this: "You are a test agent. Here is a user story: [paste one]. Plan your testing steps, generate test cases, and identify which should be automated. Think step by step before answering."
5
Note your observations: How different were the RAG vs non-RAG answers? What did the agent reasoning look like? Save these as your Chapter 4 notes.
📋 Agent Simulation Prompt 
Role: You are an LLM-powered test agent.

Context: You have been given a new user story to test.

User Story: "As a doctor, I want to view a patient's 
appointment history so I can prepare for consultations."

Instruction: Act as an autonomous test agent. Follow these steps:
STEP 1: Identify all testable conditions from the user story.
STEP 2: Generate test cases for each condition.
STEP 3: Flag which test cases are highest priority.
STEP 4: Recommend which ones to automate.

Constraints: Think through each step before proceeding to the next.
Show your reasoning.
Output Format: Use headers for each STEP.
✅ What you'll have learned

You'll have directly experienced RAG — seeing how grounding an LLM in your documents reduces hallucinations. You'll understand why vector databases and chunking matter. The agent exercise shows you how LLM-powered agents think in steps.

Apply all 5 chapters into a real strategy doc — exam-scenario thinking
~45 min ▼
🎯 What you'll learn
Strategy Sprint
You'll write a 1-page GenAI Testing Strategy document for a fictional 5-person test team — then use an LLM to critique and improve it. This synthesises all 5 chapters and perfectly mirrors the thinking required for Chapter 5 exam questions.
Claude ChatGPT
1
Define your fictional team: 5 testers at a fintech startup. They test a mobile banking app. No AI tools yet. Some testers are using ChatGPT secretly (Shadow AI!).
2
Write your strategy using the template below. Fill in all 6 sections. Don't overthink — this is your exam practice, not a real deliverable.
3
Use LLM to critique it: Paste your strategy into Claude or ChatGPT and ask: "Review this GenAI testing strategy. Identify gaps based on ISTQB CT-GenAI best practices. Suggest improvements."
4
Identify your phase: Based on the adoption roadmap, which phase is your fictional team in? Phase 1 (Exploration)? Justify your answer in 2 sentences.
📋 Strategy Document Template 
GenAI Testing Strategy — FinTech Mobile Banking App
Team size: 5 testers | App: Mobile Banking

1. Test Objectives (What will GenAI help with?)
   e.g., Test case generation from user stories, 
   synthetic test data for security testing...

2. LLM Selection
   Tool: _____ | Reason: _____
   (Consider: cost, data privacy, context window)

3. Shadow AI Prevention
   Current risk: Testers using ChatGPT informally.
   Mitigation: _____

4. Data Privacy Approach
   What data can be sent to the LLM? _____
   What must stay internal? _____

5. Adoption Phase
   Current phase: Phase 1 / 2 / 3
   Reason: _____

6. Compliance
   Relevant standards: ISO _____, EU AI Act: _____
   
--- Paste this into an LLM and ask it to critique ---
✅ What you'll have learned

You'll have synthesised all 5 chapters into one coherent strategic view. Shadow AI, LLM selection criteria, privacy, compliance, and the adoption roadmap will all be concrete in your mind. This directly mirrors how Chapter 5 questions are framed.

Deploy · GitHub Pages

Deploy This Workbook to GitHub

Host your own copy for free on GitHub Pages. Share it, customise it, add your notes.

1
Create a GitHub Account (if you don't have one)
Go to github.com → Sign up → Free plan is perfect. Verify your email.
2
Download the Project Files
Download index.html, README.md, and prompt-library.md from this workbook to your computer. Put them in a folder called istqb-genai-workbook.
3
Create a New Repository
On GitHub: Click "+" → New repository → Name it istqb-genai-workbook → Set to Public → Click "Create repository".
4
Upload Your Files
Option A (easy — no terminal): On your new repo page → "Add file" → "Upload files" → drag all 3 files → Click "Commit changes".
# Option B — terminal (if you prefer Git CLI) git init git add . git commit -m "Initial: ISTQB CT-GenAI workbook" git branch -M main git remote add origin https://github.com/YOUR_USERNAME/istqb-genai-workbook.git git push -u origin main
5
Enable GitHub Pages
In your repo: Settings → Pages (left sidebar) → Source: "Deploy from a branch" → Branch: main → Folder: / (root) → Save. Wait 2 minutes.
6
🎉 Your site is live!
Your workbook will be available at:
https://YOUR_USERNAME.github.io/istqb-genai-workbook
Bookmark this URL. Share it. Every time you push a new commit, the site updates automatically in ~60 seconds.
+
Add Your Prompt Library as You Go
As you complete each project, add your best prompts to prompt-library.md and push to GitHub. By Week 4 you'll have a complete study artifact to review before the exam.
# Quick update workflow git add prompt-library.md git commit -m "Add Chapter 2 few-shot prompts" git push
💡 Pro tip: Add your completed strategy doc, comparison notes, and prompt library to the repo. By the time you sit the exam, your GitHub repo becomes a complete portfolio of your CT-GenAI practical learning — useful for job interviews too!
